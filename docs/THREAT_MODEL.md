# Threat model (v0.4.0)

Scope: a single user running the backend on their own machine, reached from a browser on the same machine. Hosted, multi-user and remote use are **out of scope until authentication exists**. This build must not be exposed to the internet.

| # | Threat | Current mitigation | Residual risk | Test |
|---|---|---|---|---|
| T1 | **Unauthenticated access** to the API by another device, a malicious website or DNS rebinding | Every `/api/` route needs the per-install token (cookie for same-computer browser, pairing link otherwise, or Bearer); Host allowlist; Origin check on writes; binds to 127.0.0.1 by default | Any local process running as the user can read the token file; the token travels in clear over plain HTTP if you bind to the LAN (use TLS at a reverse proxy); a stolen phone keeps access until its device is removed in Devices (or `python -m app.auth revoke <id>`) | `test_auth.py` (route sweep of every API operation, pairing, Host, Origin), `test_devices.py`, e2e pairing tests |
| T2 | **Cost abuse** through the BYOK or server-key proxy | Rate limit (30/min per IP); external providers can be disabled; billing acknowledgement in the UI | The rate limiter is in-memory and per IP; server keys are usable by anyone who can reach the API (see T1) | `test_llm_rate_limit_*`, `test_external_providers_can_be_disabled` |
| T3 | **SSRF**: making the backend call arbitrary hosts | Provider is an enum; URLs are fixed; the Ollama URL comes from operator env with scheme validation; no redirects | An operator could point the Ollama URL at an internal host on purpose | `test_invalid_ollama_base_url_falls_back_*` |
| T4 | **Secret leakage** of API keys | Keys are never logged or returned; validation errors drop inputs; keys travel in bodies, not URLs; the UI never stores keys | A key typed in the browser is visible to browser extensions | `test_validation_errors_do_not_echo_api_keys`, `test_server_side_key_*`, e2e localStorage check |
| T5 | **Leaking provider/internal details** in errors | Bodies are classified, never forwarded | — | `test_provider_errors_are_classified_without_leaking_bodies` |
| T6 | **XSS** through model output or memories | All rendering uses `textContent`; CSP `script-src 'self'`, no inline scripts | `style-src 'unsafe-inline'` is still allowed (CSS injection only) | `test_frontend_has_no_inline_scripts_*` |
| T7 | **Clickjacking** | `X-Frame-Options: DENY`, `frame-ancestors 'none'` | — | `test_security_headers_*` |
| T8 | **Denial of service** with large bodies | 256 KB body limit, including chunked bodies; field length limits | Slow-loris and similar need a reverse proxy | `test_oversized_bodies_*` |
| T9 | **Prompt injection** through memories or chat | The system note labels memories as untrusted context; the chat cannot trigger any action | The model may still follow injected text in its *answer*. There are no tools, so no actions | — (relevant once tools exist) |
| T10 | **Arbitrary code execution** through the desktop endpoint | Off by default; enum allowlist; `confirm: true`; `shell=False`; no arguments from the client | If enabled with no auth (T1), anyone reachable can open those 3 apps | `test_desktop_*` |
| T11 | **Silent audio upload** | Dictation is user-initiated per click, and the UI states that the browser vendor's service is used | Vendor processing is outside ATLAS's control | — |
| T12 | **Dependency compromise** | Ranged pins; `pip-audit` run manually | No lockfile or hash pinning yet; audit not in CI | — |
| T13 | **Malicious documents / files** | Only CSV, parsed in the browser with size, row and column limits | — | — |
| T14 | **Lost/stolen device** | SQLite file in the user profile (OS account permissions; `0700` dir on Linux/macOS) | The DB and backups are not encrypted by ATLAS; rely on full-disk encryption (BitLocker/FileVault) | — |
| T15 | **Cross-user data leakage** | Single-user design | Any shared deployment would mix users | — |
| T17 | **Memory exposure** through the unauthenticated API | Server storage is off in production mode; data dir is created `0700` on Linux/macOS; `secure_delete` | Anyone who can reach the API locally can read memories (see T1); the DB is not encrypted | `test_storage_is_off_in_production_unless_enabled` |
| T18 | **Runaway or duplicated background work** | Bounded queue (50), per-task timeout (600 s), max 20 parts, idempotency keys, connect-only/one-step retries | — | `test_queue_is_bounded`, `test_task_timeout_is_enforced`, `test_idempotency_*` |
| T19 | **Silent cloud sends from tasks** | Cloud tasks start in AwaitingApproval; approval must match the SHA-256 of the task's parameters; keys are held in memory only and never written to SQLite | Approval is a click by whoever can reach the API (T1) | `test_cloud_tasks_wait_for_approval_bound_to_parameters` |
| T20 | **Prompt injection in text given to summarize** | Text is labelled as data in the system note; tasks have no tools or actions | The summary itself can be manipulated | — |
| T21 | **Device credential theft or pairing-link leak** | Other devices never get the install token: each gets its own random token, stored only as a SHA-256 hash in `devices.json` (0600). Pairing codes are single-use, expire in 10 minutes, at most 5 outstanding, held in memory only. Devices cannot pair or remove other devices. `rotate` revokes every device. An unreadable device file fails closed | A pairing link seen by someone else within 10 minutes can be used once; device cookies travel in clear over plain HTTP on the LAN | `test_devices.py`, e2e `test_owner_pairs_a_second_device_*` |
| T22 | **Agent abuse: an injected or mistaken request makes ATLAS act on the PC** | Typed actions only (no shell, no free text reaches a process); each action waits for approval of its exact parameters; the agent is off unless enabled on the PC; file actions are read-only, limited to approved folders, and refuse paths that resolve outside (including through links); limits on size and time; every approval names the approver | A paired phone can approve actions, so a stolen unlocked phone could list file names until it is removed in Devices; file names themselves may be sensitive | `test_agent.py`, `test_windows.py::test_file_actions_*`, e2e `test_pc_action_*` |
| T23 | **A tunnel or reverse proxy on the PC turns every visitor into the owner** (they connect from 127.0.0.1) | Automatic owner login needs a loopback client, a loopback Host name and no forwarding headers (`X-Forwarded-For`, `Forwarded`, `X-Real-IP`, `Tailscale-User-Login`, `CF-Connecting-IP` and others); cookies get `Secure` over HTTPS | A proxy that strips all forwarding headers and rewrites Host to `localhost` would still look local. The guide recommends Tailscale Serve, which adds them; not verified with real Tailscale | `test_devices.py::test_a_proxy_on_this_computer_*`, `test_redteam_actions.py` |
| T24 | **A paired device skips approval through the old direct launcher** (`confirm: true` is just a flag) | `/api/desktop/launch` refuses paired devices; they must use approved tasks | The owner session can still launch directly, which equals clicking on the PC | `test_redteam_actions.py::test_paired_phone_cannot_use_the_direct_launcher` |
| T25 | **File writes destroy or leak data** (overwrite, write outside the folder, write to a Windows device name) | Only new files: the name is checked (letters, digits, space, `- _ . ( )`; no `..`, no leading dot, no `CON`/`NUL`/`COM1`… names); the folder must resolve inside an approved folder; the file is written to a temporary name and linked into place, which fails if the name exists. Each write is an approved task showing name, folder and size | A user can still approve a misleading file. Excel cells are stored as text, so no formula runs, but a user who later edits the file in Excel can add formulas | `test_file_actions.py`, `test_redteam_actions.py::test_new_files_*`, `::test_existing_files_*` |
| T26 | **Trash used to remove or reach files outside the folder** | Only one regular file per approved task; the file's parent must resolve inside the approved folder; links and folders are refused; files move to ATLAS's trash, never deleted; restore never overwrites | The trash lives in the ATLAS data folder and is never emptied by ATLAS, so sensitive files stay on disk until the user removes them | `test_redteam_actions.py::test_trash_*`, `::test_restore_never_overwrites_*` |
| T27 | **Prompt injection through indexed documents** (a file says "ignore your instructions…") | Excerpts are labelled untrusted data in the system prompt; chat has no tools, so a model's reply cannot create tasks or actions; only the user turns on "Use my documents" | The answer itself can be manipulated or wrong; the user sees which files were used | e2e `test_note_is_written_indexed_searched_and_used_in_chat` checks the label and sources |
| T28 | **Document text leaves the PC** | Indexing stays local; excerpts are sent only when "Use my documents" is on, and the settings show a warning when the provider is cloud | Excerpts sent to a cloud provider are subject to its retention terms. Anyone signed in (owner or paired device) can search the index | — |
| T29 | **Speech model download or audio misuse** | Download only on owner request from the PC (paired devices get 403), with size shown and confirmation; audio limited to 10 MB / 120 s, transcribed in memory, not stored | The model comes from Hugging Face (Systran/faster-whisper-*) over HTTPS without a pinned hash | `test_voice.py` (mock engine) |
| T30 | **Browser actions open something harmful** (a `file:` or `javascript:` URL, a router or cloud-metadata page, ATLAS's own API, a look-alike domain) | Only http(s); no embedded logins; localhost, private, link-local, `.local` and non-global IPs refused; the approval card shows the host in `xn--` form; search words are URL-encoded so they cannot change the address; each open is an approved task | A public site the user approves can still be malicious and sees the browser's cookies. Hostnames that resolve to private addresses (DNS) are not checked | `test_redteam_actions.py::test_only_public_web_pages_*`, `::test_search_words_*` |
| T31 | **Automations act without the user** | They only create tasks; PC actions and cloud model tasks still wait for approval every time; API keys are never stored; at most 50 | Local model tasks run unattended (they only write text). A paired phone can create automations | `test_automations.py::test_pc_actions_from_automations_still_wait_*`, `::test_api_keys_are_never_stored` |
| T32 | **Fallback silently sends local chats to a paid cloud** | Off unless the owner configures it on the server and the user ticks it in chat; a cloud fallback needs the server key; the answer names the fallback | The tick is remembered in that browser | `test_fallback.py` |
| T33 | **Hands-free listening captures private speech** | Off by default, visible indicator, only with local Whisper (never the browser's online service), clips transcribed on the PC and not stored, stops when leaving the chat screen | While on, every sound clip in the room is transcribed on the PC | e2e `test_hands_free_*` |
| T34 | **A stranger uses the online ATLAS and spends the owner's AI quota** | The function answers chat and model lists only for a signed-in device; the first device claims the site (an access code can be required); others need a one-time pairing link from the owner; Netlify rate limit of 60 requests a minute per visitor; output capped at 2,048 tokens; input capped at 100,000 characters | Whoever opens a fresh, unclaimed site first becomes its owner unless `ATLAS_ACCESS_CODE` is set; the owner then sees "This ATLAS is private" and must reset the claim in Netlify Blobs | `netlify/tests/cloud.test.mjs` (`chat and models need a signed-in device`, `first device claims…`, `access code…`) |
| T35 | **Provider keys leak from the online version** | Keys exist only as Netlify environment variables read inside the function; the browser never receives or sends one (`cloud.js` drops any typed key); status lists providers without keys; provider error text is shortened and never includes the request | Anyone with access to the Netlify project can read the variables | `status lists only providers with a key and never returns keys`, `provider errors become a clear message without the key` |
| T36 | **Stolen device token (online)** | Random 256-bit tokens, stored server-side only as SHA-256 hashes; the owner can remove a device; pairing codes are single-use and expire after 10 minutes | A token lives in the phone's localStorage, so anyone with the unlocked phone, or script running on the site, can use it; XSS defences are T6 | `pairing links work once…`, `the owner can remove a device…` |
| T37 | **Chat data on third parties (online)** | The chat notice names the provider and its billing before the first message; memories and history stay in the browser | Messages and saved memories sent with them reach the provider (and Netlify, which runs the function) under their terms | — |
| T38 | **Netlify credits spent through AI Gateway** | Gateway providers are labelled "(via Netlify AI Gateway)" and the notice says the cost comes from Netlify credits; a key the owner sets takes priority | Credits are shared with the owner's other Netlify projects | `status lists only providers…` (gateway label) |
| T16 | **API docs exposure** | Docs are off when `ATLAS_ENV=production` | — | `test_api_docs_are_off_in_production` |

Before any hosted or remote use: add per-device credentials and TLS (T1), a persistent rate limiter (T2), TLS at a reverse proxy, a lockfile with CI audit (T12), and server-side storage with access control (T14/T15/T17).
