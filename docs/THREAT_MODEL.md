# Threat model (v0.27.0)

Scope: the web app at https://atlas-os-sm.netlify.app. Anyone can open it. There is no ATLAS account;
each visitor brings their own AI key. The only sign-in is the optional, read-only Google one (T52). Threats that applied only to the PC version (removed in
0.15.0) are in the Git history of this file.

| # | Threat | Current mitigation | Residual risk | Test |
|---|---|---|---|---|
| T6 | **XSS** through model output or memories | All text is inserted with `textContent`; CSP `script-src 'self'` plus Google's sign-in script (`https://accounts.google.com/gsi/client`), no inline scripts | `style-src 'unsafe-inline'` is still allowed (CSS injection only) | e2e `attacks in the browser …` |
| T9 | **Prompt injection** through memories or chat | The system note labels memories as untrusted context; chat has no tools, so a reply cannot act (Live with PC control can: see T53) | The model may still follow injected text in its answer | — |
| T11 | **Audio sent to the browser vendor** | Dictation and Live listen only after a tap, and the UI says when the browser's speech service is used (Chrome, Edge, Safari); Brave and Firefox use T50 instead | Vendor processing is outside ATLAS's control | — |
| T20 | **Prompt injection in text given to summarize** | Text is labelled as data in the system note; tasks have no tools | The summary itself can be manipulated | — |
| T34 | **Visitors spend the site owner's AI quota or Netlify credits** | No server-side keys: the function reads no environment variables and ignores Netlify AI Gateway injection; every request must carry the visitor's own key; fixed official provider URLs; rate limit 60 requests a minute per visitor; output capped at 2,048 tokens, input at 100,000 characters | Each call still counts toward the owner's Netlify function and bandwidth allowance; a flood could use it up | `the site owner's environment keys and AI Gateway are never used` |
| T35 | **A visitor's key leaks** | Sent only over HTTPS with that visitor's own requests; never stored or logged by the function; only to the chosen provider's official URL; provider errors that repeat the key are redacted; tasks keep keys in memory only | A remembered key sits in localStorage, readable by anyone using the unlocked device or by script on the page (T6 limits script to the site's own files). Netlify processes the request | `provider errors become a clear message, with any echoed key removed`, e2e remember/untick checks |
| T36 | **The function used as a proxy** | Only the provider hosts in code, only chat, model-list, speech and transcription calls, validated model IDs and message shapes; extra fields are dropped; rate limited | Someone with their own valid key can use the site as a proxy to that provider | `chat input is validated before any provider call`, `attack.test.mjs` |
| T37 | **Chat data on third parties** | The chat notice names the provider and that the visitor's own account is billed, before the first message | Messages and saved memories sent with them reach the provider (and Netlify) under their terms | — |
| T38 | **Other websites call the function** | Cross-site requests (`Sec-Fetch-Site`) or a foreign `Origin` get 403; only `application/json` (415 otherwise); no CORS headers; body size checked before reading | Scripts outside a browser can send any headers; they still need their own key and hit the rate limit | `attack.test.mjs` |
| T39 | **Injection** (HTML/script in replies or memories, prompt injection asking for the key) | `textContent` everywhere and a strict CSP; the key is sent in its own field, never inside the prompt, so a model cannot repeat it; no tools for a model to call | A model can still be talked into wrong or harmful text; treat answers as untrusted | e2e `attacks in the browser …`, `attack.test.mjs` |
| T40 | **Auto-switch spends money** | Auto-switch only moves between free providers; a paid provider is used only when the visitor picks it | A free provider can start charging; ATLAS cannot know | e2e auto-switch test |
| T42 | **A crafted backup file** (Devices → Import) | Only items whose name starts with `atlas.` and whose value is text are written, at most 5 MB; the user confirms first; nothing in the file is run, and everything is shown with `textContent` | A file from someone else can replace your memories, key or Google client ID with theirs (the Google consent screen then names their app), so only import your own files | e2e devices test |
| T43 | **A backup file leaks keys** | Export leaves AI keys out unless the user ticks "Include my AI keys", which warns that anyone with the file can use them | A file exported with keys is as sensitive as the keys | e2e devices test |
| T44 | **Automations spend money or act unseen** | Only plans (with the AI Chat provider and key, never a guessed paid one) and reminders; nothing runs while ATLAS is closed; each run is logged and shown | A plan automation uses the provider's quota on every run | e2e automations test |
| T45 | **Malicious or oversized files** (images, PDFs) | Only PNG, JPEG, WebP, GIF and PDF, checked as base64; at most 4 files and about 3 MB; chat bodies up to 5 MB, other routes 20 KB; files go only to the chosen provider and are never stored; images are re-encoded in the browser | A PDF's text can carry instructions to the model (prompt injection); the model provider sees the file | `cloud.test.mjs` attachment validation |
| T46 | **A chat summary carries injected instructions** | The summary is written by the model from the chat, sent as marked context ("not instructions"), shown to the user, and removed with Clear all or when a covered message is deleted | A summary can still be wrong or keep an injected line; the user can read and clear it | e2e chat extras |
| T47 | **Camera, microphone or screen used without the user knowing** | Only on the Live screen and only after a tap; the browser asks permission; the picture is shown on screen while on; a frame is sent only with a question, to the AI Chat provider; everything stops when Live ends or the user leaves the screen; `Permissions-Policy` allows camera and screen capture for this site only | Listening goes through the browser's speech service (Google or Microsoft in Chrome and Edge) | e2e Live test |
| T48 | **Real-time voice sends the key and microphone audio off the device** | Real-time voice is chosen by the user and starts only on a tap. The browser opens a WebSocket only to `wss://generativelanguage.googleapis.com` (the CSP `connect-src` allows nothing else) with the user's own Gemini key in the URL, as Google's API requires; ATLAS's server never sees the audio. Audio and pictures stream only while Live is on and stop on End, mute or leaving the screen; history keeps text only | The key is in the WebSocket URL (encrypted by TLS, not logged by ATLAS). Google's own data terms apply to the audio; free-tier Gemini data may be used by Google to improve its products | e2e real-time test, cloud test |
| T49 | **Paid ChatGPT voice runs up a bill** | Never chosen for the user: it waits for a tick saying it is billed to their OpenAI account; the screen says it is paid; it runs only while Live is on and stops on End or leaving the screen. The browser connects only to `wss://api.openai.com` (CSP); the key goes as a WebSocket subprotocol (browsers cannot send headers), not in the URL | OpenAI recommends short-lived tokens for browsers; here the user's own key stays in their own browser, as with every other provider in ATLAS | e2e ChatGPT voice test |
| T50 | **Speech recordings sent off the device** | Only after a tap on Dictate or Live, only in browsers without their own speech service; one short WAV per thing said goes through `/cloud/transcribe` to the user's own Groq or Gemini key (OpenAI only if chosen); nothing is stored; the function accepts only WAV under about a minute | Groq's and Google's own data terms apply. Test my voice setup records exactly one second, only after a tap, and sends it the same way | cloud and e2e speech tests, e2e voice check |
| T51 | **Answer text sent off the device to be spoken** | Only when Read aloud is on or Live turn by turn answers; the answer (markdown removed, at most 1,500 characters a request) goes through `/cloud/speak` to Google with the user's own Gemini key, or to OpenAI only if it is the chosen provider (paid); the voice name must be letters only; nothing is stored; without such a key the browser's own voice is used | Google's and OpenAI's data terms apply; free Gemini keys may be used by Google to improve its products | cloud and e2e voice tests |
| T52 | **Google Calendar and Gmail access misused or leaked** (a stolen token, a wider scope, injected text in email subjects or event titles, a hostile client ID) | Only `calendar.readonly` and `gmail.readonly` are requested; the code has only GET calls, and Gmail is read as headers (sender, subject, date), never message text. The token comes from Google's token client, is kept in a variable in `google.js` (never in storage, never sent to ATLAS's server or an AI model) and is revoked with Google on Sign out; it expires after about an hour. The browser talks only to the hosts the CSP lists: `accounts.google.com/gsi/` (script, frame, connect), `www.googleapis.com/calendar/v3/`, `gmail.googleapis.com/gmail/v1/`, `oauth2.googleapis.com/revoke`. Titles and subjects are shown with `textContent`. The client ID is checked against Google's format and is never in the code. `Cross-Origin-Opener-Policy` was relaxed from `same-origin` to `same-origin-allow-popups` so the sign-in pop-up can report back | Any script running on the page could use the token while it is valid, so T6 (strict CSP) matters more; Google's script is now trusted code on the page. Gmail read access is broad (Google calls it a restricted scope) even though ATLAS shows only 10 subjects. Someone who pastes a stranger's client ID signs into the stranger's Google app (the consent screen names it). Pages this site opens in pop-ups keep a link to it (`same-origin-allow-popups`); ATLAS's own external links use `rel="noopener"` | e2e Google test, cloud CSP test |
| T53 | **Live controls the PC wrongly or against the user** (prompt injection from a web page, file name or picture; a misheard command) | The ATLAS PC helper offers only typed actions with checked arguments; no shell, no delete or overwrite, no opening programs or scripts, no Win+R/Win+X, no settings, installs or shutdown. Typing, non-trivial shortcuts and closing a window need a click on a Windows Yes/No box on the PC (default No, 60 s timeout, one at a time) that names the target window, and the action then goes only to that exact window (refused if it is no longer in front; this was wrong before 0.26.0). Every action and every answer is printed in the helper window; closing it stops everything | A tricked model can still open apps, websites, files in the user folder, press media keys or lock the PC without asking. File names from `find_files` reach the AI provider. Old Office formats (.doc, .xls, .ppt) can hold macros; Office asks before running them | `pc-helper/test_atlas_helper.py`, e2e PC control test, real test on the owner's PC |
| T54 | **Other websites or programs drive the PC helper** | Listens on 127.0.0.1 only; requires `Host` 127.0.0.1/localhost (DNS rebinding) and the `Origin` `https://atlas-os-sm.netlify.app` exactly (deploy previews are refused since 0.26.0: anyone can open a pull request on the public repository and get a preview of their own code); JSON only (no simple form posts); pairing needs the 6-digit code shown on the PC (one use, 10 min, 5 tries); the token is 256-bit random, bound to the origin, stored hashed, and never put in Devices backups | Script running on the ATLAS site (see T6) can use a paired token for actions that do not ask. Malware already on the PC is out of scope | helper server tests |
| T55 | **Phone actions used against the user** (a tricked model prepares a call to a premium number, a message to someone else, or a bad link) | The model can only prepare: ATLAS shows the full action (who, number, text, place or address) and a button; nothing happens until the user taps it, and the phone's own app shows it again before sending. Links are only `tel:`, `sms:`, `https://wa.me/`, Google Maps, YouTube, or an http(s) address for open_website (`javascript:` and other schemes are refused); they open with `rel="noopener noreferrer"`. Contacts are read only when the user picks one, and only that contact's name and number | A user who taps without reading can still call or message the wrong person | e2e phone action tests |
| T41 | **Lost or shared device** | Nothing is synced; "Remember my key" is a visible choice; Clear all and Delete all memories | Data stays in that browser until cleared | — |

Netlify injects its free-plan badge script (`/.netlify/scripts/hud`) into every page; the CSP blocks its inline part, so it cannot run code in the page, at the cost of one console error. CodeQL (`.github/workflows/codeql.yml`) and Dependabot (`.github/dependabot.yml`) report new code and dependency problems automatically.

No tool, test or review can promise zero vulnerabilities. This project has not had an
independent security audit.
